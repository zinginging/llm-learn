# RSI 论文阅读笔记

核验日期：2026-10-26。本笔记按“修改对象—提出器—评价—继承—证据边界”阅读。数字均为作者实验，不是本地复现。9 篇 arXiv 论文 PDF 已下载并提取正文，另读取 ACL Gödel Agent PDF；页面、代码和会议证据见 [来源记录](来源与版本核验.md)。

## 1 阅读方法

先找方法与实验设置，再看结果和限制。摘要常将不同 split、预算和基线压缩到一句话，不宜直接抄为比较表。重点追问：是否换了模型？评价任务是否参与搜索？新版本是否成为下一轮提出器？是否测过外部未见任务？

## 2 STOP：改进器作为自己的输入

- 论文：Eric Zelikman、Eliana Lorch、Lester Mackey、Adam Tauman Kalai，*Self-Taught Optimizer (STOP): Recursively Self-Improving Code Generation*，[arXiv v3](https://arxiv.org/abs/2310.02304v3)。首次 2023-10-03，论文正文标注 COLM 2024。
- 问题：LM 支持的代码优化程序是否能通过优化自身获得更好的下游搜索策略？
- 方法：seed improver 生成候选并按 utility 选择，再将其源码交给 improver；下一轮使用得到的新程序。
- 证据位置：正文方法中的 improve_algorithm 示例及下游任务实验；优化对象包括搜索策略，不更新 LM 权重。
- 局限：任务集合窄、依赖 utility；作者明确不称 full RSI。本地未运行生成代码、模型 API 或沙箱实验。
- 学习价值：把“求解对象”和“求解方法”分开，再理解二者如何通过自引用连接。

## 3 Gödel Agent：修改运行时逻辑

- 论文：Xunjian Yin 等，*Gödel Agent: A Self-Referential Agent Framework for Recursively Self-Improvement*，[ACL 2025 正式论文](https://aclanthology.org/2025.acl-long.1354/)。
- 方法：允许读取、更新自身逻辑，通过运行时 monkey patching 改变类或模块；正文 §2 说明核心机制。
- 与理论区别：借鉴自引用思想，不等于实现原始 Gödel Machine 的数学证明机制。
- 局限：开放设计空间是研究目标，不能据此断言无约束、全局最优或必然连续增长。其语言理解与数学任务设置不与编码 Agent 直接比较。
- 学习价值：思考“能修改哪些组件”和“能否可靠评价这些修改”是两个独立问题。

## 4 SICA：效用决定下一轮 meta-agent

- 论文：Maxime Robeyns、Martin Szummer、Laurence Aitchison，*A Self-Improving Coding Agent*，[v2](https://arxiv.org/abs/2504.15228v2)。2025-04-21 首发；OpenReview 的 ICLR 2025 SSI-FM workshop 页面与 arXiv 预印本记录分别保留。
- 方法：在版本归档中找当前较优 Agent，使其分析并实现代码改进，再运行 benchmark。§3 明确区分这种变化的 meta-agent 与固定 meta-agent。
- 评价：§3 的效用对任务分数权重 0.5，成本与时间各 0.25；成本归一化上限为每题 10 美元，时间 300 秒；超时另有惩罚。这些是实验设置，不是推荐生产阈值。
- 结果：§4/Table 1，SWE-bench Verified 固定随机 50 题子集约 17%→53%；也有 LiveCodeBench 与合成编辑、符号定位任务。15 轮 API 费用约 7000 美元，模型主要为 Sonnet 3.5 v2，推理子 Agent 用 o3-mini。
- 局限：最高解题分数不等于最高综合 utility；不据此推断完整 SWE-bench 排名或今天可复现费用。
- 学习价值：部署成本本身应进入评价，不只优化成功率。

## 5 DGM：保留多样化 Agent 祖先

- 论文：Jenny Zhang、Shengran Hu、Cong Lu、Robert Lange、Jeff Clune，*Darwin Gödel Machine: Open-Ended Evolution of Self-Improving Agents*，[v3](https://arxiv.org/abs/2505.22954v3)。首次 2025-05-29，v3 正文标注 ICLR 2026。
- 方法：冻结基础模型，Agent 修改自己的代码，基于任务表现将候选加入开放式归档；可从不同祖先分支。
- 设置：§4.1 自修改阶段使用 Claude 3.5 Sonnet New；SWE-bench 评价也用它，Polyglot 评价用 o3-mini。80 轮、每轮一个新候选。
- 样本：§4.2 先测基本任务，再扩展；SWE-bench 使用 Verified 子集，强候选扩展到 200 题；Polyglot 演化用 50 题子集，另做完整 benchmark 评估。
- 结果：§4.4 SWE-bench 指标 20.0%→50.0%；Polyglot 演化子集 14.0%→38.0%，完整 Polyglot 为 14.2%→30.7%。不同分母不可混写。
- 消融：固定 meta-agent 和去掉开放式探索的对照，有助于理解自改与归档各自作用。
- 局限：冻结权重、有限任务与预算、选择噪声；任务分数上升不意味着一般意义的无限递归。

## 6 SEAL：双层学习与 self-edit

- 论文：Adam Zweiger 等，*Self-Adapting Language Models*，[arXiv v2](https://arxiv.org/abs/2506.10943v2)，另有 [NeurIPS 2025](https://papers.neurips.cc/paper_files/paper/2025/hash/6b41e04c41726e2a60e456d0a2b961ab-Abstract-Conference.html)。首次 2025-06-12。
- 方法：模型生成用于自身适应的文本/指令，梯度更新后在任务上评价，外层学习产生有效 self-edits。§3—4 包含 ReST-EM 等具体流程，不能一概写成所有实验都用 PPO。
- 知识任务：§4.2，Qwen2.5-7B 在无 passage 上下文的 SQuAD 问答中，冻结 base=32.7%，仅 passage 更新=33.5%，base 自生成数据=39.7%，GPT-4.1 生成数据=46.3%，SEAL=47.0%。这里比较的是适应方案，不是 GPT-4.1 自身问答准确率。
- 少样本任务：§4.1，Llama-3.2-1B-Instruct；筛选 11 个训练任务与 8 个评估任务，要求基本模型在最佳 TTT 配置下有可解性，不代表整个 ARC-AGI。
- 工程：仓库说明原始实验可用两张 A100/H100，其他配置需调整；本次未训练。
- 局限：适应的数据选择、遗忘、训练成本；参数更新不直接证明优化器递归增强。

## 7 AlphaEvolve：评价驱动的算法程序搜索

- 论文：Google DeepMind 团队，*AlphaEvolve: A coding agent for scientific and algorithmic discovery*，[v1](https://arxiv.org/abs/2506.13131v1)。论文 2025-06-16，首篇官方博客 2025-05-14，日期不同。
- 方法：LLM 生成与修改程序，通过自动评价和演化保留有用变体；适用于算法、内核与计算基础设施。
- 与 RSI 的关系：可改进训练模型所用组件，但目标程序变化不等于优化系统自身也被递归改变。
- 代码边界：alphaevolve_results 仓库提供数学结果与验证代码，不据此声称完整服务开源。第三方 OpenEvolve 与原始系统应分开归因。

## 8 AIDE²：检验“更会研究”和“更会自我改进”

- 论文：Dhruv Srikanth、Bingchen Zhao、Dixing Xu、Yuxiang Wu、Zhengyao Jiang（Weco AI），*Recursive self-improvement of AI research agents*，[v1](https://arxiv.org/abs/2609.26457v1)。2026-09-22 预印本。
- 方法：§2 的外层提出 Agent 改写，内层在 AI R&D 任务上搜索解；公共信号辅助内层搜索，私有信号给外层评分，内层候选选择策略可修改而外层保留最优规则固定。
- 设置：§3，外层使用 Claude Opus 4.7，内层 Gemini 3 Flash，各循环模型固定。8 天运行有 100 个节点：初始版本加 99 个提案，7 次接受的改进。
- 泛化：§3.3 分开测试未参与选择的四个基准；只能按其具体预算和任务说明迁移，不能当作所有研究领域有效。
- 关键反证边界：§3.6 ignition test，两种外层 Agent 各 3 个种子、50 步、相同起点；作者认为不足以确证改进后的 AIDE47 更高效。该段比宣传标题更能限定强 RSI 结论。
- 评价器问题：§3.5 提到修复某任务隐藏评分脚本的故障，应区分评价基础设施修补和 Agent 策略提升。
- 版本冲突：论文摘要 reward hacking 为 55%→32%，官方早期博客为 63%→34%；不把两组数值混成同一结果。本报告不以它们作独立安全保证。

## 9 RRSI：控制适应性过拟合

- 论文：Peng Xia 等，*RRSI: Regularized Recursive Self-Improvement of Agent Harnesses*，[v3](https://arxiv.org/abs/2609.24972v3)。2026-09-21 首发，2026-10-04 v3，按预印本引用。
- 方法：约束 proposer 的编辑预算与探索轨迹，selector 使用 critic/pruner 限制题目特化、冗余和高成本改动，底座策略冻结。
- 结果解释：§4/Table 1—3 同时报告 evolve split、OOD、tokens 和不同 policy；摘要的 up to 是具体设置中的最大改善，不是统一平均值。
- 消融：去掉约束可能使 evolve 分数更高，OOD 更差，说明“开发集更好”不能单独作为胜出依据。
- 学习价值：优化提出空间、选择空间及复杂度，而不只是无上限增加候选。

## 10 PAST-Bench：经验的效果与路径归因

- 论文：Shuhan Xue 等，*PAST-Bench: Benchmarking the Foundations of Recursive Self-Improvement in Personal Agents*，[v1](https://arxiv.org/abs/2608.04003v1)，2026-08-04 预印本。
- 方法：有序 fresh-session 任务，配对比较有/无持久经验，并追踪保存、检索和更新路径。
- 范围：26 个场景、204 个 episodes，四类能力；作者比较 7 个底座、4 个框架。
- 解释：任务分与机制证据分开；相同表面增长可能来自不同机制。记忆存在、文件保存或自动生成 Skill 均不足以证明有效经验迁移。
- 局限：评测个人 Agent 的在线演化基础，不直接证明训练算法研发或无限 RSI。

## 11 AI4AI-Bench：提交新的学习机制还是只改运行参数

- 论文：Yizhe Chi 等，*AI4AI-Bench: Benchmarking LLM Agents in Algorithmic Design for Recursive Self-Improvement*，[v1](https://arxiv.org/abs/2608.20318v1)，2026-08-20 预印本。
- 方法：10 个冻结仓库/算法家族，每任务 4 小时、1 张 B300 探索；提交代码从头重跑最多 12 小时，固定隐藏评价，与原算法使用相同流程比较。
- 分数：作者定义 0 为无信息模型、0.1 为原算法、1 为任务最优。29 配置/6 系统整体均值 0.166，最佳系统 0.250，不能按准确率百分比解释。
- 学习价值：评估机制创新与等预算复跑，不能只看代码 diff 数量。可用它审查 AI 研究 Agent，但基准本身不构成 RSI 实现。

## 12 两个边界基线

[Self-Refine v2](https://arxiv.org/abs/2303.17651v2) 的生成、反馈、修订发生在测试时，未额外训练；[Reflexion v4](https://arxiv.org/abs/2303.11366v4) 将语言反思放进 episodic memory，不更新模型权重。本轮主要核对其原始摘要与方法定位，不将其摘要中的跨任务平均增长或 HumanEval 结果搬来与编码 harness 比榜。

本轮没有复现这些模型实验，也没有按论文运行付费、自修改或 GPU 训练程序。可执行部分仅为 [评估门禁教学实验](../scripts/evaluation_gate_demo.py)。
