# 三项目上手：建库、检查证据、生成答案

本文命令针对 2026-11-09 核对的源码提交。**安装命令与真实 API 示例尚未端到端执行**；已验证的是源码接口静态匹配、示例语法和离线教学计算。请先在测试环境使用少量非敏感数据，参见[验证记录](../intermediate/验证记录.md)。

## 1. 准备共同输入

使用 Python 3.12 分别建环境：GraphRAG 当前要求 `>=3.11,<3.14`，另两者要求 `>=3.10`；选择 3.12 是本教程的共同起点，不代表所有可选依赖都没有平台限制。准备 Git、Python 与 uv 包管理器。

在本主题目录执行：

```bash
TOPIC="$(pwd)"
python scripts/ppr_learning.py
python scripts/export_graphrag_input.py
mkdir -p tmp/tutorial
```

输入是 [11 篇虚构短文、6 个问题](../input/企业知识样例.json)。先用它检查时间、别名、干扰项和无答案行为，再替换为真实文档。微型语料可能形成很少的社区，不足以展示 GraphRAG 全局覆盖优势。

后面各节均从本主题目录开始。`TOPIC` 要在每个新 shell 重新设置。`tmp/` 已被仓库忽略，下载、虚拟环境、索引与密钥文件均不纳入 Git。

## 2. Microsoft GraphRAG

### 2.1 安装与固定版本

当前仓库已是 monorepo，用 workspace 安装可同时固定组件源码：

```bash
TOPIC="$(pwd)"
git clone https://github.com/microsoft/graphrag.git tmp/tutorial/graphrag
cd tmp/tutorial/graphrag
git checkout 34b2b67ae4601ad0b47bcd179fbe3f2a23aa0857
uv sync --all-packages --no-dev --python 3.12
source .venv/bin/activate
graphrag --help
```

首次克隆才执行 `git clone`，已有目录先确认版本，避免重建或覆盖。此路径固定了项目代码；完整环境复现还应保留锁文件、平台和模型版本。若只需要发行包，可在独立环境安装 `graphrag==3.3.0`，但其代码与本文主分支快照不能仅凭同一包版本号就视为完全相同。

### 2.2 初始化配置

```bash
graphrag init --root "$TOPIC/tmp/graphrag-work" --model gpt-4o-mini --embedding text-embedding-3-small
```

会生成 `settings.yaml`、`.env` 等。**以这次安装实际生成的文件为准**。本次核对的 `config/init_content.py` 模板使用：

```yaml
completion_models:
  default_completion_model:
    model_provider: openai
    model: gpt-4o-mini
    auth_method: api_key
    api_key: ${GRAPHRAG_API_KEY}

embedding_models:
  default_embedding_model:
    model_provider: openai
    model: text-embedding-3-small
    auth_method: api_key
    api_key: ${GRAPHRAG_API_KEY}
```

这只是模型配置片段，不能代替整个生成文件。当前仓库入门文档仍展示过另一种 `models:` 结构，Python 范围也与包元数据不一致；复制旧 YAML 是常见报错原因。配置密钥 `GRAPHRAG_API_KEY`，不要把真实值放进命令示例、Git 或截图。

示例模型沿用项目已有 OpenAI 适配接口，不代表已核实本账号当前能调用。Azure 或兼容服务需检查 provider、endpoint、部署名、JSON 输出和 embedding API；“兼容 OpenAI”不保证所有参数一致。

### 2.3 建库与查询

下面会触发模型 API 并可能计费：

```bash
graphrag index --root "$TOPIC/tmp/graphrag-work" --method standard
graphrag query "北辰与南桥项目有哪些共同风险和各自风险？" --root "$TOPIC/tmp/graphrag-work" --method global
graphrag query "截至2026年11月9日，北辰项目负责人的任职公司总部在哪？" --root "$TOPIC/tmp/graphrag-work" --method local
graphrag query "北辰项目的人员变动与风险有什么联系？" --root "$TOPIC/tmp/graphrag-work" --method drift
graphrag query "澄海科技总部在哪？" --root "$TOPIC/tmp/graphrag-work" --method basic
```

当前 query 是位置参数；不要直接套用旧文章的 `--query` 写法。命令未显式指定查询模式时，当前源码默认 global；教程显式给出模式以免误用。

建库后先打开配置指向的 output 目录，检查实体、关系、原文映射、社区与报告。Parquet 是表格文件，可用 pandas 读取；先查看 schema，再选列，避免不同版本字段改名造成错误。

小语料没有形成预期社区时，先检查抽取与社区层级。不要立即通过扩大生成模型来掩盖索引问题。中文入门先走 standard；fast 的名词短语/共现路线需要单独验证中文提取能力。

### 2.4 更新与验收

当前 CLI 有 `graphrag update --help` 和 update 路线。增量文件识别、输出合并、社区报告更新范围应按当前版本和实验确认，不能简单把原文件改掉再假设全部派生都已失效。

验收时保存源文档→text unit→实体/关系→报告→答案引用的映射。对要求删除的资料，先验证原文、派生报告、向量、缓存均无法继续泄露；没有验证前不承诺文档级彻底删除能力。

## 3. LightRAG

### 3.1 安装

重新进入本主题目录，并使用独立环境：

```bash
TOPIC="$(pwd)"
git clone https://github.com/HKUDS/LightRAG.git tmp/tutorial/lightrag
cd tmp/tutorial/lightrag
git checkout abc733b5c4f371fa39b3396b504a7309bd1531ad
uv venv --python 3.12
source .venv/bin/activate
uv pip install -e .
```

Python 导入名为 `lightrag`，PyPI 发行包名为 **`lightrag-hku`**。本次源码包版本为 1.5.8，GitHub latest release 则是 v1.5.7；需要严格复现本文时使用上面的提交。不要混装另一个同名包。

### 3.2 运行顺序

设置 `OPENAI_API_KEY` 环境变量后：

```bash
python "$TOPIC/scripts/lightrag_demo.py" --help
python "$TOPIC/scripts/lightrag_demo.py"
python "$TOPIC/scripts/lightrag_demo.py" --answer
```

默认脚本依次导入共享语料，并输出 naive/local/global/hybrid/mix 的检索上下文；`--answer` 才额外生成最终答案。关键词提取和建库已经会调用 LLM，所以默认运行并非免费模式。

最重要的生命周期为：

```text
LightRAG(...) → await initialize_storages()
  → await ainsert(...)
  → await aquery(..., QueryParam(...))
  → await finalize_storages()
```

本例的 embedding 函数使用官方已封装的 `openai_embed`，对应 `text-embedding-3-small`、1536 维；换模型时必须同时核对向量维度、token 限制、归一化和索引兼容性，使用新的独立存储目录做试验。不要套一个错误维度的包装，也不要只更改模型名字后继续复用旧索引。

示例显式关闭 rerank，以便观察基础召回；生产若配置重排服务，另做开关消融和时延对比。`top_k`、`chunk_top_k`、实体/关系/token 总预算共同影响上下文。

当前 `ainsert()` 是固定 token 切块的便捷入口；服务器的 parser/chunker 选项与 SDK 入口并不完全等价，不能认为 WebUI 上能选的所有切块方式都能通过同一个 `ainsert` 参数使用。

### 3.3 服务化与更新

要用 WebUI/API，在该隔离环境安装项目 API extra，例如 `uv pip install -e '.[api]'`，按此提交的 `env.example` 配置，再使用 `lightrag-server --help` 查看启动项。源码安装的 WebUI 是否需要另外构建，以该提交说明为准。

先只在测试范围监听，配置鉴权与访问策略后再对外提供服务。当前默认文件后端适合小规模验证；迁移数据库时要同时考虑 KV、vector、graph、doc-status，不能只迁移 Neo4j。

新增文档可再次插入，但“同 ID 替换原文”不应未经验证就当成原子 upsert。对删除、重建、图编辑、失败重试分别做验收，并在调用后查看文档状态。多存储没有全局事务，须测试中断和恢复行为。

## 4. HippoRAG 2

### 4.1 安装

重新进入本主题目录，第三个独立环境：

```bash
TOPIC="$(pwd)"
git clone https://github.com/OSU-NLP-Group/HippoRAG.git tmp/tutorial/hipporag
cd tmp/tutorial/hipporag
git checkout d5c8329422e0a0b834a15874545cb6a74b4f9b26
uv venv --python 3.12
source .venv/bin/activate
uv pip install -e .
```

此提交包版本为 **2.0.0a5**，包含 alpha 标记；最新 GitHub release v1.0.0 不能代替本次第二代源码。依赖含固定版本 torch/transformers 等，首次安装可能较大，平台与 CUDA 组合需检查。远程模型示例不意味着 Python 包完全没有 ML 依赖。

### 4.2 分开看检索和问答

设置 `OPENAI_API_KEY` 后：

```bash
python "$TOPIC/scripts/hipporag_demo.py" --help
python "$TOPIC/scripts/hipporag_demo.py"
python "$TOPIC/scripts/hipporag_demo.py" --answer
```

默认导入语料、使用 `retrieve()` 输出原文、分数、来源元数据和图种子；`--answer` 将已有 `QuerySolution` 传给 `rag_qa()`，避免重复检索。

当前无 gold 评估参数时：

```text
retrieve(queries=[...]) → list[QuerySolution]
rag_qa(queries=[...])   → (solutions, response_messages, metadata)
```

传入 gold 文档/答案会改变评估及返回结构，不要把 `rag_qa()` 返回值直接当成一段字符串。分数是检索排序信号，不是 confidence。

本例用远程 `text-embedding-3-small` 避免初学者先部署默认研究用的 NV-Embed-v2。它与论文 embedding 不同，不能用例子结果宣称复现论文性能。

### 4.3 存储与生命周期

`with HippoRAG(...) as rag` 在结束时清理资源。当前索引含 `index_manifest.json`，绑定模型、端点、归一化、预处理和组件身份等信息。改变这些条件应使用新的 `save_dir`，或按官方兼容规则迁移；不能删除清单来绕过检查。

当前存在增量 `index()` 和 `delete(docs_to_delete=...)`。此提交的删除函数接收**已索引的文本内容字符串列表**，先与存储中的文本精确匹配，不接收 source_id 列表；有预处理/切块时尤其要核对实际存储内容与来源映射。先用临时索引测试删除后召回、重载与重加。旧图如果缺少来源边信息，当前实现会拒绝可能留下过期事实的删除。

如使用自建 OpenAI 兼容端点，可配置 `llm_base_url`、`embedding_provider="openai"`、`embedding_base_url`，并用 `llm_api_key_env` / `embedding_api_key_env` 指定密钥环境变量名。当前代码要求标准 usage 记账信息；接口能回答一句话不代表能通过整条抽取与缓存流程。

## 5. 三者共同的调试顺序

| 现象 | 优先检查 |
| --- | --- |
| import 或配置字段报错 | 包名、当前提交、Python、独立环境；GraphRAG 生成配置与旧教程是否混用 |
| 图里没有目标对象 | 原文解析、切块边界、模型输出、实体别名与归一化 |
| 图有对象但没召回 | 关键词/三元组种子、向量兼容、模式、top-k、token 裁剪 |
| 召回正确但答案错误 | 时间、否定、主体混淆、生成提示、证据不足时是否拒答 |
| 删除后旧知识仍出现 | 源文档、共享实体/关系、报告、向量、缓存、进程内状态与失败恢复 |
| 费用或延迟太高 | 分阶段调用数和 token；先看建库、recognition/map、重排，再看最终生成 |

成功的第一步不是“页面能打开”，而是能说明每条答案依赖哪些有效原文。完整验收见[选型与评估方案](选型与评估方案.md)。
