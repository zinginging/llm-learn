## 2. 三篇论文应该怎样读

### 2.1 [G1] Microsoft GraphRAG

**From Local to Global: A Graph RAG Approach to Query-Focused Summarization**，Darren Edge 等。arXiv 首次发布 2024-04-24，本次阅读 v2（2025-02-19）。[摘要及版本](https://arxiv.org/abs/2404.16130v2) · [PDF](https://arxiv.org/pdf/2404.16130v2)。这里以该预印本版本记录，不推断其他出版状态。

研究问题：当问题需要理解整套资料时，只找几个语义近邻文本块不一定覆盖全局；如何预先组织资料，使全局概括更完整？

方法主线：文本块→实体关系图→社区层级→社区摘要→问题相关的 map-reduce。重点不是“所有复杂问题都做图遍历”，而是为 query-focused summarization 建立可扩展的中间语义表示。

**实验口径：**两套约 100 万及 170 万 token 的播客/新闻语料；每套由用户角色、任务和问题生成流程得到 125 个全局问题。比较多个社区层级、直接对原文做全局摘要、向量检索基线；主要用 LLM 成对评价全面性、多样性、赋能性和直接性，且重复比较。

论文报告 GraphRAG 在部分全局问题评价维度优于向量基线。这里不把 LLM 偏好胜率改写成“事实准确率”，也不把这类全局问题的优势推广到全部事实问答。阅读顺序建议为 §3 方法→§4.1 设置→结果与附录提示，再思考：如果问题是精确金额统计，实验是否支持直接使用该方法？

**局限与复现注意：**合成问题与模型评价可能有偏差；社区摘要有信息压缩；实体归并影响覆盖。当前项目的 Local、DRIFT、Basic 和 Fast 等工程能力，需要结合新文档理解，不应全部归入这篇原始论文的实验结论。

### 2.2 [L1] LightRAG

**LightRAG: Simple and Fast Retrieval-Augmented Generation**，Zirui Guo、Lianghao Xia、Yanhua Yu、Tu Ao、Chao Huang。arXiv 首次发布 2024-10-08，v3 更新 2025-04-28。[arXiv](https://arxiv.org/abs/2410.05779v3)。本次全文阅读采用 **Findings of EMNLP 2025 正式会议版**，页 10746–10761：[会议页面](https://aclanthology.org/2025.findings-emnlp.568/) · [PDF](https://aclanthology.org/2025.findings-emnlp.568.pdf)。不要把会议版 PDF 的哈希记成 arXiv v3 的哈希。

研究问题：如何在实体级细节和更抽象的关系/主题之间同时检索，并减少处理社区报告的开销？

方法主线：图索引结合向量表示；问题提取低层和高层关键词，分别匹配实体与关系，再收集相关上下文。增量算法把新抽取的节点边并入原图；不要求使用 Microsoft 那套分层社区报告检索。

**实验口径：**UltraDomain 的 Agriculture、CS、Legal、Mix 四类语料，约 61.9 万至 508 万 token；每类生成 125 个问题。主要指标是 LLM 评价的全面性、多样性、赋能性及 Overall 成对偏好。会议版说明使用 GPT-4o-mini，chunk size 1200，gleaning=1。

**一个可核对的效率数字：**会议版表 6 报告平均查询时间 LightRAG 11.2 秒、GraphRAG 23.6 秒。这只是该文实现、任务与配置的作者实验，不能推断当前版服务、其他模型和任意并发下都快同样倍数。

表 3 中“GraphRAG 610×1000 tokens、LightRAG <100 tokens”讨论的是特定检索处理环节，不包括整条回答的所有模型输入输出。不能把它宣传为“每次完整问答只需要不到 100 token”或“系统总成本降低几千倍”。

**局限与版本注意：**论文中的增量比较针对当时 GraphRAG 方案；当前 Microsoft 代码有 update 路线，不能据此宣称它永远必须完全重建。原始论文也不能证明当前系统默认解决时间冲突。现代 `mix`、WebUI、parser、存储恢复能力应另按当前源码核对。

建议阅读 §3 双层方法→§4 与 §9 实验设置→§4.3 效率→当前源码的关键词和召回分支；把“论文设计”与“今天 SDK 默认”分别记下。

### 2.3 [H1] HippoRAG 2

**From RAG to Memory: Non-Parametric Continual Learning for Large Language Models**，Bernal Jiménez Gutiérrez、Yiheng Shu、Weijian Qi、Sizhe Zhou、Yu Su。arXiv 首次发布 2025-02-20，本次阅读 v2（2025-06-19）。[arXiv](https://arxiv.org/abs/2502.14802v2) · [PDF](https://arxiv.org/pdf/2502.14802v2) · [ICML 2025 / PMLR 页面](https://proceedings.mlr.press/v267/gutierrez25a.html)。

研究问题：怎样把持续增加的外部知识组织成支持事实检索、关联检索和长文本理解的记忆，而不重新训练模型权重？

方法新增部分：passage 节点把上下文纳入图；完整问题检索事实三元组；LLM recognition 过滤候选；短语与段落共同产生重启分布，再由 PPR 排序原文。§3.2–3.5 是理解第二代的关键。

**实验口径：**覆盖 NQ、PopQA、MuSiQue、2Wiki、HotpotQA、LV-Eval、NarrativeQA 等任务。分别报告问答 token F1 与证据 passage recall@5；结构化方法比较使用 Llama-3.3-70B-Instruct 生成结构、NV-Embed-v2 作检索器。

| 原文位置 | 作者实验中的观察 | 正确的解释范围 |
| --- | --- | --- |
| 表 3，MuSiQue | NV-Embed-v2 recall@5=69.7，HippoRAG 2=74.7 | 提升 5.0 个百分点，属于该证据召回任务 |
| 表 2，2Wiki | NV-Embed-v2 QA F1=61.5，HippoRAG 2=71.0 | 提升 9.5 个百分点，不能改写成准确率提升 9.5% |
| 表 4，三类多跳任务 | 完整方法平均 recall@5=87.1；去掉 passage node=81.0 | 支持该设置下 passage 节点有用，不保证所有任务受益 |
| 表 4，同一组消融 | 去掉 recognition filter 平均为 86.4 | 筛选的收益大小依数据变化，在线调用成本应单独算 |

**跨论文比较警示：**该文自己的 LightRAG 复现，在这组简答 F1 任务上结果很低。不能据此说当前 LightRAG 对所有知识问答都不可用。它与 LightRAG 原文的全局开放式问答、LLM 偏好指标不同，代码版本、模式、提示与答案格式也会影响结果。若业务是简答事实问答，应该把它当作需要检查的风险信号，再用自己的统一基准验证。

该文表 3 未列 GraphRAG/LightRAG 的 passage recall；这是论文当时实现与评估口径的限制，不代表今天它们无法返回原文上下文。

附录 F / 表 12 的耗时实验基于 MuSiQue 的 **11,656 passages**，Llama-3.3-70B-Instruct 部署在 **4 张 H100** 上；显存统计排除了共享模型权重。不能拿其中数字当作本环境耗时、消费级机器配置或完整服务显存需求。

**失败模式：**recognition 筛掉关键事实、相似短语错连、扩散未覆盖全部桥接证据。持续学习实验把语料逐段加入，考察固定问题随语料扩展的表现，不等于已验证生产中的所有修改、遗忘、权限撤回和多租户场景。

第一代可补读 [HippoRAG: Neurobiologically Inspired Long-Term Memory for Large Language Models，arXiv 2405.14831](https://arxiv.org/abs/2405.14831)。不要把第一代 NER-to-node 机制直接当作第二代默认查询机制。

## 4. 本次能证明什么，不能证明什么

已核对论文全文的关键方法、评测设置、部分结果表和作者源码接口；保存了 PDF 哈希，但全文只在可删除的 tmp 中。源码快照可以支持“这个提交的实现有这些路径和默认值”。

离线 PPR 演算可以证明本主题人工图的相关性扩散与时间反例；不能证明 HippoRAG 2 的实际种子质量。AST 检查可以证明示例使用的参数存在；不能证明依赖安装成功、服务可用、API 计费、中文效果、更新删除 SLA 或项目间性能排名。

待验证项与统一实验设计见[选型与评估方案](选型与评估方案.md)。
