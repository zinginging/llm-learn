# 环境、命令与可选Qwen运行

本地已验证Linux、Python 3.12.14、PyTorch 2.5.1+cpu、TRL 0.28.0、Transformers 4.57.3、Datasets 4.4.1、Accelerate 1.11.0。完整环境记录见[依赖快照](../intermediate/环境依赖.txt)。下面CPU安装方式对应Linux；其它平台使用PyTorch官方支持的构建。

## 1. CPU版从零运行

先安装uv，再在本主题目录执行：

```bash
uv venv tmp/venv --python 3.12
uv --system-certs pip install --python tmp/venv/bin/python \
  'torch==2.5.1+cpu' --index-url https://download.pytorch.org/whl/cpu
uv --system-certs pip install --python tmp/venv/bin/python -r scripts/requirements.txt

python scripts/check_verifier.py
tmp/venv/bin/python scripts/sft_demo.py
tmp/venv/bin/python scripts/rl_demo.py
```

首次安装需要网络；默认两个训练demo不需要网络、模型下载、GPU、密钥或付费API。若uv版本不支持`--system-certs`，按该版本使用系统CA的方式配置，不关闭TLS验证。

CPU版使用26,976参数的随机GPT-2架构及本地字符tokenizer。它不是预训练大模型，不要将其测试结果用于选择生产训练算法。完整脚本接受`--help`，训练步数、学习率和输出目录可调整；调整应以验证集和预先确定的计划为依据。

## 2. 两个阶段产物

| 阶段 | 输入 | 输出 |
| --- | --- | --- |
| SFT | 随机微模型或外部预训练模型，prompt/completion | `tmp/sft`模型、tokenizer、初始身份与SFT指标 |
| GRPO | SFT目录，prompt与奖励元数据 | `tmp/grpo`模型、tokenizer与GRPO指标/日志 |

`rl_demo.py`默认要求先有`demo_manifest.json`，避免误用不兼容checkpoint。换实验时用不同`--output`目录；运行记录不会自动保留旧版本。

若想完整复现本次CPU环境，可参考完整依赖快照；`requirements.txt`只固定核心训练库，传递依赖随后发布时可能不同。固定随机种子不保证跨硬件/库版本逐位相同。

## 3. 可选：真实预训练Qwen模型

模型：`Qwen/Qwen2.5-0.5B`，核验的固定修订：

```text
060db6499f32faf8b98477b0a26969ef7d8b9987
```

这是base模型，demo使用普通算术字符串，不依赖chat template。换成Instruct模型或messages数据，应调整模板和评测格式。模型版本记录在[元数据](../intermediate/Qwen模型版本.json)；本次没有下载权重或执行此路径。

另建虚拟环境，并按显卡、驱动和操作系统安装匹配的[PyTorch CUDA构建](https://pytorch.org/get-started/locally/)，再安装相同`requirements.txt`。CPU构建不能因为加了CUDA参数就使用GPU。下面假设该环境位于`tmp/gpu-venv`：

```bash
HF_HOME="$PWD/tmp/hf-cache" tmp/gpu-venv/bin/python scripts/sft_demo.py \
  --model Qwen/Qwen2.5-0.5B \
  --revision 060db6499f32faf8b98477b0a26969ef7d8b9987 \
  --output tmp/qwen-sft --steps 120 --lr 0.00002

HF_HOME="$PWD/tmp/hf-cache" tmp/gpu-venv/bin/python scripts/rl_demo.py \
  --checkpoint tmp/qwen-sft --output tmp/qwen-grpo \
  --steps 80 --lr 0.000005
```

首次下载需要网络和存储空间，模型/数据许可需按使用方式核对。脚本使用全参数FP32训练、不用LoRA或vLLM，也不自动选择混合精度；其目的是减少演示依赖，不是最佳显存配置。GRPO还保留KL参考模型并生成候选，显存需实测，不给未经验证的最低显存保证。实际大模型训练可再评估LoRA、BF16、梯度检查点和推理后端。

只有25条训练输入，不能据此评估Qwen整体能力。程序自动计算答案只是教学奖励，不应把它当成“所有推理任务都能用一个正则评分”的方案。

## 4. 常见故障和诊断

- **奖励一直0：**先打印少量训练候选，检查任务是否可解、EOS/解码、输出契约、奖励函数参数和正确答案映射；不要立即增大学习率。
- **奖励组无差异：**区分全部错、全部对和采样缺乏多样性。ε只防除零，不能增加区分信息。
- **训练reward升高但测试不变：**检查过拟合、奖励漏洞、分布覆盖和测试独立性；不能靠挑更容易测试题解决。
- **OOM：**区分模型、优化器、参考模型、采样批、输出长度和缓存。调整候选数要同步满足生成批的整除条件。
- **输出不停止：**检查训练结束符、PAD/EOS处理与completion mask；不能只靠强行截断掩盖。
- **API参数报错：**确认使用固定TRL版本。本例0.28.0使用`processing_class`、`max_length`与`generation_batch_size`，不同教程版本可能不同。

本次只支持示范的单进程配置；多卡必须重算有效batch、生成批和采样分组，不直接照搬单卡参数。
