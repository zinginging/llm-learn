# 来源与版本核验

核验日期：2026-10-26。使用官方模型 API 文档、MCP 规范和 Agent Skills 开放格式；能力选型是基于这些机制的工程归纳。示例仅使用标准库与虚构数据，不调用真实模型或协议服务。

## 2 与本文实现的对应关系

本文只展示内部归一化调用，不采用供应商响应结构或完整 MCP 报文。脚本的 model_tool_definition 将目录字段适配到一种模型函数定义形态；生产环境还需检查模型支持的 JSON Schema 子集、工具命名和结果格式。

dispatch 仅验证教学样本要求的字段和月份，并检查显式注入的 Identity。它不是完整 JSON Schema 验证器，不包含身份认证和真实数据源行权限。业务身份与模型参数分离是应用设计，不由标准库 dataclass 自动保证身份可信。

没有编写真实 Skill 包或调用宿主加载器，目录树只是教学结构。没有声称 SKILL.md 对任意宿主具有可执行或授权效果。

## 3 验证与局限

- 实际运行 [离线示例](../scripts/call_boundary_demo.py)，观察适配前后的业务后端结果一致、不同教学身份返回不同数据、五种不合法或不受支持的请求被拒绝。
- 命令、输出、解释器版本和脚本 SHA-256 保存在 [验证记录](../intermediate/验证记录.json)。
- 不验证模型是否选择正确工具、协议握手与认证、远程网络行为、Skill 触发、提示注入抵抗或生产性能。
- 工作流、语义层与四种机制的组合是设计建议，没有对所有框架和服务做兼容验收。

## 4 后续真实接入验收

先以一个只读业务 API 跑通模型调用闭环，分别记录工具选择、参数、结果和回答正确率；再使用双方支持的 MCP SDK/版本运行相同查询，核对身份、分页、错误和结果一致性。Skill 要测任务触发、资源加载与输出质量，不能仅检查文件存在。外部写操作另测授权、幂等、重复请求与恢复。
