# 四项目语义层 PoC 验收方案

本方案为待执行实验，不表示四项目已跑通。

## 统一业务定义

按支付时间统计已支付订单，以查询时点确认的退款扣减，金额为 CNY 分。取消订单不计入。主表 orders、退款 refunds、商品 items 各自有唯一 ID，后两者均与订单一对多。

教学数据：O1 属租户 A，支付 10000 分，退款 1000 和 2000，明细两行；O2 属 A，支付 20000，无退款，明细一行；O3 属 B，支付 30000，退款 5000，明细两行。A 净收入 27000，全局 52000。

先在订单粒度聚合退款，再计算净收入。若筛商品类型，先定义整单计入还是按明细分摊；没有这项业务定义，项目间差异不能直接判为引擎错误。

## 三阶段执行

1. 结构化请求：分别验证 Cube、MetricFlow 和 Wren 的基本指标、关系、时间和拒绝行为，不引入 LLM。
2. Agent 请求：固定模型、工具与预算，比较中文同义词、歧义、旧例子和权限错误。
3. 交换：固定 Ossie 规范与转换器，导出再导入实际需要的路径。当前未证明存在四者完整互换链路。

## 测试记录

每例保存项目 commit、运行依赖、模型与数据库版本、建模文件、输入、身份、编译 SQL、执行结果、错误与最终判定。缓存测试额外记录刷新时刻和命中状态。

结果状态分为通过、失败、不支持、未执行。不得把不支持或未执行记为通过。

## 发布门槛

| 维度 | 验收原则 |
| --- | --- |
| 业务正确性 | 黄金值、单位、过滤与时间定义一致 |
| 关系 | 明细行数变化不能无故倍增金额 |
| 权限 | 服务、缓存和数据库均隔离，测试直接接口绕过 |
| 错误处理 | 未知指标明确拒绝，不静默换成近似指标 |
| 上下文 | 旧例子不覆盖现行定义，含来源和版本 |
| 交换 | 报告未表示与未执行特性，不只验 schema |
| 运维 | 能回滚模型、更新索引并解释结果变化 |

性能固定硬件、数据、并发、身份和超时，分冷、热和刷新后报告 p50/p95、扫描、失败率与成本。Ossie 测转换速度和等价覆盖，不加入查询服务延迟排名。
