# 当前业务的接入建议、发布与验收

2026-11-17会话重建；沿用2026-11-16研究结论。已知方向是统一业务语义、Agent取数、MCP/API和企业文档解释；真实schema、IAM、来源版本、规模、SLA与预算尚未取得。方案是有条件建议，不是已部署系统。

## 1. 分开三类业务问题

| 请求 | 事实来源 | 处理路径 |
| --- | --- | --- |
| “净回款是什么，用哪份数据？” | 批准术语、schema、owner和血缘 | 目录发现与语义解析 |
| “华东上月净回款多少？” | 审核公式、源数据与权限 | 受控结构化执行 |
| “为什么下降，规则是否变了？” | 指标拆解、政策、工单等 | 数值+授权证据，区分观测与推测 |

数据接口建立在可管理的来源/Binding和结构适配之上，不要求每个Agent逐个手写底层接入。[平台设计](08_多源接入管理与元数据及上下文组装设计.md)

## 2. 起步组合与选择

目录优先DataHub/OpenMetadata二选一；已有成熟目录与指标服务时复用。Ontop、GraphRAG、Semantica按缺口引入，不是五个必装。

| 需求 | 建议 |
| --- | --- |
| 来源配置、元数据、owner和治理 | 主目录加接入控制面 |
| 异构业务服务统一访问 | 独立适配/数据访问层或已有平台 |
| 指标口径 | 已有API、批准SQL、Cube/MetricFlow等执行绑定 |
| 本体到关系数据访问 | Ontop单域PoC |
| 文档局部事实 | 普通RAG基线 |
| 跨文档主题/关系 | GraphRAG候选 |
| 来源、记忆、失效组装 | Semantica或自建代码基线 |

## 3. 明确业务契约

教学指标net_receipts定义：订单粒度、人民币分、paid状态、实付减退款、按支付时间划业务月、Asia/Shanghai左闭右开。退款按当前记录归属原订单支付月；这不是用户既定财务口径，真实业务须确认退款归期和历史快照。

身份由服务端验证，tenant/地区来自可信授权，不能由模型自报。metric、schema、mapping、本体与权限策略分别版本化。目录描述与执行公式通过ID/版本关联，避免在prompt、映射、目录里各维护一份漂移公式。

## 4. 一次请求的完整流程

```text
用户身份与场景
 → 固定配方、授权和语义版本
 → 发现批准资产/业务定义
 → 调用注册的Binding及受控查询
 → 规范化结构、校验单位/粒度/时点/完整性
 → 按授权域检索文档，排除过期和撤回依赖
 → 合并数值和证据，组装引用及预算
 → 类型化ContextBundle → 后续Agent/工作流
```

建议能力接口：discover_assets、resolve_metric、query_metric、retrieve_evidence、compose_context。它们是本报告建议的契约，不声称五项目原生提供同名完整工具。可先用HTTP/SDK，最后加MCP适配；MCP协议不替代数据治理和执行。

没有资产、权限拒绝、源不可用、投影未就绪、超时与完整查询后的零行都应分别返回，不能统一当成“没有数据”。

## 5. 项目接入责任

DataHub/OpenMetadata负责目录、术语、owner、质量与血缘，先关写工具。历史SQL只作候选案例，批准并绑定版本后才使用。OpenMetadata Agent SPARQL的资产权限过滤边界需单独验收；其ingestion许可不能按根Apache概括。

Ontop作为本体查询Binding，先验证单源映射与黄金SQL，再由模板/网关调用；源端权限和池化身份不能缺失。

GraphRAG负责文档支路，保留原文位置、有效期、授权域和派生依赖。普通RAG和Basic作对照，不能所有请求都走Global。

Semantica可先仅承担来源注册、撤回依赖和grounded组装。默认AgentContext是否走到选定约束必须实测；不能因为类存在就说所有入口默认开启。

## 6. HBase条件分支

会话提到HBase/MCP，但未提供rowkey、结构、索引及现有服务。目录能登记HBase不等于Ontop支持原生扫描。

有稳定业务API时优先受控复用；通过Phoenix/Trino等SQL层时，核对实际版本、驱动、方言、下推和权限。历史跨分区分析可评估入分析仓库，保留同步水位。目录、工具协议和数据执行层职责分别明确，本次没有连接真实HBase。

## 7. 发布、缓存与失效

一次语义发布关联metric、ontology、mapping、schema指纹、目录revision、文档索引和授权策略版本。不同系统不能提供全局快照时，定义可接受时差和数据时间，不能伪称原子事务。

缓存key绑定语义版本、结构化参数、数据水位和可信授权范围/策略版本。只按自然语言或用户名缓存不足以处理租户和角色变化。

撤回文档要定位相关摘要、实体描述、向量、缓存和Agent记忆。无法同步完成清理时，先阻止旧依赖进入回答；删除源文档不自动等于全部派生遗忘完成。

## 8. 已运行的教学案例

[SQLite脚本](../scripts/contract_demo.py)检查净回款250元、明细重复关联350元、退款更新后240元，以及时区、租户和证据版本。

[多源原型](../scripts/source_management_demo.py)将同一资产的SQL行、REST和类HBase结构映射为同一结果，只选择一个权威Binding，避免把三个副本误加为750元；检查版本、格式、权限与必需/可选结果。

这些是自建离线实验，不调用五框架或真实来源，不证明其生产权限或性能。结果见[验证记录](../intermediate/验证记录.md)。

## 9. 分阶段交付与准入

| 阶段 | 交付物 | 准入条件 |
| --- | --- | --- |
| 0 业务契约 | owner、口径、时间/单位、权限、黄金值 | 业务批准且有反例 |
| 1 受控执行 | 身份、固定查询/API、审计 | 黄金值和越权用例通过 |
| 2 管理与适配 | 来源UI/配置、Schema、映射、发布/监控 | 实际格式、变更、分页和源权限通过 |
| 3 文档解释 | 普通RAG/GraphRAG对照 | 引用、授权和撤回链通过 |
| 4 可选本体 | Ontop映射与等价性 | 源方言、结果、性能与权限可接受 |
| 5 可选框架 | Semantica上下文试点 | 依赖、预算、持久化和并发检查通过 |

测试覆盖fan-out、NULL、时间、退款归期、跨租户、脱敏、版本、索引重建、无答案和故障。有限用例100%通过只作为准入条件，不能宣称线上永远正确。

耗时分别统计发现、适配、检索、规划、源执行、传输和LLM生成，带样本数、并发与冷/热条件；生产阈值由业务约定。真实连接器、拓扑、资源与排期仍需实际系统信息。
