# 成果持久化与防丢失

2026-11-17。此次问题能确认的是：报告曾生成，但当时未进入Git；后来环境检出远端时不含该目录。旧环境没有完整文件审计，不能认定已经查到具体删除命令。

## 1. 改变交付标准

本地文件存在、可点击路径、示例运行成功，只说明当前工作区有结果。持久化需要完成：

```text
产出 → 检查未跟踪/修改 → 内容与链接校验 → 明确路径暂存
     → commit → push → 在线核验远端SHA和交付文件 → 报告保存状态
```

已有本任务commit/push授权时，阶段结果验证后及时执行；长任务按可审阅里程碑保存，避免全部积压到最后。没有授权或明确要求不提交时，说明“仅在工作区，尚未进入远端”，不能当作已远端保存。

本地commit也可能不随新环境带回；必须核验push。不能只看本地origin/work，因为它可能是旧的追踪引用。

## 2. 只读检查工具

在llm-learn根目录执行：

```bash
python 202611_agent上下文平台五项目对比/scripts/persistence_check.py --verify-remote
```

工具先检查整个仓库的未跟踪/未提交内容，再检查[交付文件清单](../input/交付文件清单.json)，最后在线执行`git ls-remote`比较目标分支与本地提交。远端SHA相同，且所需文件在该提交及工作区存在时，才返回`REMOTE_VERIFIED`和退出码0。

| 结果 | 含义 |
| --- | --- |
| LOCAL_CHANGES | 有未跟踪、已修改或已暂存未提交内容，不能完成持久化验收 |
| MISSING_DELIVERABLES | 清单中的文件没有进入当前提交，或本地缺失 |
| LOCAL_ONLY | 仅做本地检查，远端没有核验，退出码2 |
| REMOTE_DIFFERS | 可能未推送、远端领先或分叉，先核查；不自动强推 |
| REMOTE_UNAVAILABLE等 | 网络/认证/分支等问题，远端状态未知，不能算成功 |
| REMOTE_VERIFIED | 所需文件在当前提交，在线远端分支SHA相同 |

这是严格交付检查：远端领先也可能包含本地成果，但工具不会未经fetch/包含关系分析就宣布成功。它不修改Git或自动发布，不删除/重置文件，不输出凭据。

清单以仓库根为基准，覆盖文档、脚本、输入与来源记录；不包含tmp源码下载、缓存、模型权重或密钥。新主题可通过`--manifest`传入自己的清单。根AGENTS和README也纳入当前清单。


使用tmp内一次性仓库和本地bare远端，验证整个未跟踪目录、修改、暂存、未推送、缺失文件、远端不可用与保存成功等状态。只操作测试仓库，不连接真实远端。

## 4. 仍需明确的边界

AGENTS规则与脚本是可执行的检查流程，不能阻止主机在两次检查之间出故障，也不是平台级文件快照或已安装的后台监控。删除动作需事先检查未提交内容，不用git clean/硬重置清理成果目录。

任务交付应包含提交哈希、远端分支和核验状态。若需要抵御Git托管端误删除，再配置独立持久存储的仓库镜像或备份；把备份放在同一临时工作区不解决该风险。本次未配置外部备份或定时任务。
