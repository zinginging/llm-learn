# AI-Ready 数据实践模板与验收

以下为教学设计，与[主文档](../output/构建ai-ready数据学习调研.md)配合使用，不是官方标准或已完成的实验。

## 1 任务卡

| 字段 | 示例 |
| --- | --- |
| 目标 | 支持人员查询指定日期的退款规则 |
| 用户 | support；其他角色不能读取内部说明 |
| 来源 | 审批政策；交易事实由账本查询 |
| 正确条件 | 版本、期限、例外与引用均正确 |
| 无答案 | 说明缺少依据，不补造政策 |
| 非目标 | 不自动批准或执行退款 |
| 更新要求 | 按业务约定时限完成全链路更新 |

## 2 最小合成资料集

准备三类政策、一份订单表和十个问题，不接真实系统：

- 旧政策：2023-01-01 至 2026-10-01 前有效，五个自然日。
- 新政策：2026-10-01 起有效，七个自然日，定制商品除外。
- 内部审批说明：仅 support 可以访问。
- 订单表：稳定 ID、金额单位、商品类型、签收时间、状态与观察时间。

时间区间约定为左闭右开 [valid_from, valid_to)。旧政策 valid_to=2026-10-01，新政策 valid_to=null。日期和规则均虚构。

题目覆盖当前、历史、跨生效日、例外、缺失签收日期、无匹配规则、无权限、表格单位、状态变化和伪指令。每题标注允许来源与必要证据。

## 3 数据契约

1. document_id 跨版本稳定，document_version 标识快照。
2. chunk_id 在同快照内唯一，可回溯原位置。
3. valid_from 必填；valid_to=null 只表示没有已知终止时间。
4. access_groups 空数组默认不可访问，不能默认为公开。
5. status=approved 才进入生产知识视图。
6. source_ref 为真实来源，模型补充背景另存字段。
7. 内容变化使依赖 chunk、向量、摘要和缓存失效。
8. 删除保留受控 tombstone，避免同步复活旧记录。

## 4 资产卡与发布清单

记录名称、负责人、来源、授权依据、用途、非用途、语言、时间范围、缺失、结构、版本与反馈入口。未知写待核实，不由模型补全成事实。

清洗记录包含原始数、通过数、隔离数、排除原因及配置。发布记录包含源快照、解析器、分块配置、嵌入版本、索引版本和题集版本。

## 5 对照实验

| 对照 | 固定条件 | 改变因素 |
| --- | --- | --- |
| 固定长度与结构分块 | 来源、模型、题集、检索数 | chunk 边界 |
| 纯向量与混合检索 | 来源、分块、读取模型 | 召回方法 |
| 无版本过滤与生效过滤 | 查询时间、题目 | 时间选择 |

另外检查权限撤销和删除是否传播到原文、索引、摘要与缓存；不把它当成训练后的模型遗忘测试。

## 6 评价记录

每题保留 query、user_role、as_of、gold_evidence_ids、expected_answer、abstain_condition、retrieved_ids、answer、citations 与最终判定。错误区分检索缺失、读取错误、过时事实和权限错误。

报告完整证据命中率、回答正确率、例外保留率、过时使用率、越权记录数、传播延迟与成本。无答案题和历史题分别报告。

关键单位缺失和无来源不应由平均分抵消。“越权为零”仅表示本次测试未观察到泄露，不是全系统保证。

## 7 实验状态模板

```yaml
experiment_id: refund-data-demo
data_snapshot: synthetic-v1
parser_version: recorded-before-run
chunk_config: recorded-before-run
model_id: recorded-before-run
eval_set_version: questions-v1
run_status: planned
results: null
```

planned 表示未执行，只有运行核对后才能填结果。

## 8 自测答案

向量化只生成检索表示，不证明来源与正确性。相同内容的订单可能是独立事件。上传时间与生效时间不同。政策不能证明交易状态。删除需处理原文、chunk、词法索引、向量、摘要、缓存及受控审计记录。

完成标准：用独立题集验证结果，能定位数据缺失与模型错误，并说明更正和删除如何传播。
