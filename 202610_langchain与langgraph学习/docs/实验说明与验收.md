# 实验说明与验收

目标是验证框架如何执行工具循环、传递身份、保存检查点与恢复任务。两个实验使用虚构人民币整数分数据，不调用外部模型。依赖安装需要网络；运行无需密钥、付费服务或真实业务数据库。

## 1 安装与运行

在主题目录执行；版本锁定按 Python 3.12 解析。显式关闭可选追踪，避免继承本机的追踪配置：

```bash
export UV_CACHE_DIR="$PWD/tmp/uv-cache"
uv venv tmp/venv --python 3.12
uv pip sync --python tmp/venv/bin/python scripts/requirements.lock
LANGSMITH_TRACING=false LANGCHAIN_TRACING_V2=false \
  tmp/venv/bin/python scripts/langchain_tool_loop.py
LANGSMITH_TRACING=false LANGCHAIN_TRACING_V2=false \
  tmp/venv/bin/python scripts/langgraph_checkpoint_flow.py
```

无需激活环境；如果已经创建，直接执行 sync 和脚本即可。tmp/ 被仓库忽略。SQLite 实验库由 TemporaryDirectory 创建，结束时清理，不保留业务状态。

如需重新解析依赖，使用以下命令，并重新验证；这会更新传递依赖，结果不一定与本次一致：

```bash
uv pip compile scripts/requirements.in \
  --output-file scripts/requirements.lock --python-version 3.12
```

## 2 LangChain 工具循环

| 验证点 | 断言或观测 |
| --- | --- |
| 工具 schema | 模型可见参数只有 month，不含 ToolRuntime/tenant |
| 模型请求 | ScriptedModel 返回固定工具名称和月份 |
| 执行身份 | 应用给 context 注入 A 或 B |
| 结果 | A=27000、B=25000，单位为人民币分 |
| 消息链 | human、ai、tool、ai |

ScriptedModel 继承真实 BaseChatModel，并实现最小生成与 bind_tools 接口。它不理解问题，不能证明 LLM 真的会选对工具、拒绝恶意请求或正确生成参数；也没有测试结构化输出 provider 策略。其用途是观察模型调用协议与框架循环的职责。

## 3 LangGraph 跨进程恢复

```text
validate → approve(interrupt)
                 ├─ 同意 → fetch → sales ───┐
                 │             └→ refunds ─┴→ combine → END
                 └─ 拒绝 → denied → END
```

驱动进程依次启动四个工作进程：同意路径暂停、同意路径恢复、拒绝路径暂停、拒绝路径恢复。同一路径沿用 thread_id，检查点由同一个 SQLite 文件保存。

| 路径 | 期望观测 |
| --- | --- |
| pause | 有 interrupt；审批函数进入一次，查询次数均为零 |
| resume yes | 新进程再次进入审批函数；sales 尝试两次、refunds 一次；净收入 27000 |
| resume no | 新进程再次进入审批函数；查询次数均为零；status=denied |

sales 第一次人为抛出 TimeoutError，retry_policy 只允许最多两次尝试，退避初始值 0.01 秒且关闭 jitter。它没有真实 I/O，也不提供延迟基准。两个分支各写独立字段；add_edge(["sales", "refunds"], "combine") 表示两者完成后的汇合条件。

“并行分支”指图调度结构，不声称这个几乎无计算的样本证明吞吐提升。实验没有模拟 worker 被强杀、检查点写入中断或数据库锁竞争。

## 4 生产化需要另测什么

| 场景 | 验收方法 | 通过标准示例 |
| --- | --- | --- |
| 真实模型工具调用 | 固定问题集、模型 ID、温度与预算 | 参数、工具与回答分别评价 |
| 缺少查询条件 | 缺日期、币种、指标口径 | 追问或明确拒绝，不能静默猜测 |
| 多租户 | 同问题切换可信身份，尝试伪造 tenant/thread_id | 数据与历史均不越权 |
| 大结果 | 大行数、分页、截断 | 明确告知范围，优先引用文件 |
| 进程故障 | 外部调用前后与检查点边界终止进程 | 不丢任务、不重复产生业务效果 |
| 外部写操作 | 同一幂等键多次提交 | 回执可追溯、最终效果一次 |
| 重试 | 连接故障、429、权限错误、参数错误 | 按错误类型处理，次数有界 |
| 恢复后权限变化 | 审批期间撤销角色或数据权限 | 恢复时重新校验 |
| 并发 | 多分支写相同字段、多 thread 同时运行 | reducer、命名空间与隔离正确 |
| 历史版本 | 更新图结构和 state schema 后恢复旧任务 | 明确迁移或兼容策略 |
| 性能 | 同模型、数据量、缓存和并发测 P50/P95 | 按业务 SLO 判断 |

先跑通直接 API 与单 Agent 基线，再增加编排复杂度。权限和正确性不达标时，不能用更低平均耗时替代验收。
